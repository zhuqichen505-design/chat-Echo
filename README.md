## v2.8.12：输入注入回复与长会话改进

对话设置 → 提示与记忆新增“输入注入回复”，默认关闭。开启后，界面仍显示用户原始输入，上一条模型回复的显示保持原样；后台先将上一条回复保存为“原回复 + 两个换行 + 本次输入原文”，再以用户完全自定义的触发语请求下一条回复。只追加输入原文，不附加标题、标签或固定续写模板；触发语不能仅为空白。

显示正文与模型正文分别持久保存，失败重试、重新生成复用本轮触发语，不重复追加。分支、备份与会话导入保留并映射注入关联，检索继续使用实际输入。关闭功能后新消息恢复普通发送，既有历史保持稳定显示。手动编辑正文与自动注入都保留滚动摘要正文、覆盖水位和更新时间；用户主动重新压缩或重新生成摘要时才按编辑后的原文重建，失败仍保留上次摘要。

本版同时纳入此前尚未出包的 bot、时间线和摘要修复。数据库以显式迁移升为 Room v37（20 实体），保留旧消息、时间线、设定与摘要；v35→v36 增加时间线开关，v36→v37 增加注入设置及消息关联字段。

bot 与右上状态符号整体放大，时间线和设定提取更凝练；对话设置新增独立时间线开关，关闭后不注入或后台提取，已有记录仍可查看；时间线内容改为紧凑布局。

针对普通聊天正常而压缩失败，摘要双协议共用参数，按模型能力选择输出限制字段与实际最低支持思考档位，并为推理预留完成空间；统一自定义 API 路径，支持正文数组及跨块思考标签。首轮摘要超出保存预算时改用紧凑二次语义缩短，确保小窗口实际发出第二次请求。双协议失败时保留原文和旧摘要，不用本地抽取文本计为模型成功。最终冻结验收记录 `20261018-184947-493`，脚本与 Gradle 退出 0，编译、88 套件/878 项完整单测实际执行通过，失败/错误/跳过 0，Lint 0 Error/95 Warning，输入哈希一致，差异检查退出 0；Release 构建退出 0，本机 APK 元数据、签名、内容隐私与排他复制核验通过，版本提交与 v2.8.12 标签已推送，公开唯一 APK 附件及匿名下载 SHA256 均与本机一致；仅撤下新仓库远端 v2.8.11 Release/标签，本机历史包和旧标签保留。严格本机 HTTP 回归不代替真实接口与设备验收，用户遇到的 HTTP 500 仍需新包在同一真实接口复验。

## v2.8.11：压缩重试、摘要兼容与对话恢复

自定义比例或其他压缩档位失败后，保留当前选项与“重试压缩”操作，无需改比例即可再次应用。摘要使用独立短请求：连接 10 秒、读取和写入各 30 秒、单次 HTTP 调用 45 秒；连接失败或超时不会再叠加通用重试和备用 Key 轮询。长历史需要分段处理，整次压缩可能包含多次请求，不承诺 45 秒内完成全部整理。

摘要请求按原文顺序分块，预算计入角色、消息 ID、模板、旧摘要及输出空间，保护长消息和完整字符。只有服务明确报告容量问题时才缩小失败分块；未知错误不会当作超限反复拆分。对 HTTP 500/502 且错误正文明确为 `empty response detected` 的非流式网关响应，尝试一次流式兼容通道；普通服务端错误仍按真实原因报告。空正文、只有思考、正文不完整和响应截断分别说明，失败不保存伪摘要、不推进覆盖位置，原文与上次有效摘要保留。

摘要故障不会继续拦住预算内的正常对话：发送时使用上次有效摘要、尚未摘要的完整轮次原文与必须保留的内容；同一配置的已失败摘要请求不会在每次发送时重复发起，可在面板主动重试。若完整未覆盖历史仍超出模型预算，会明确提示重试压缩或调整模型窗口，不静默丢弃原文，也不把超长请求直接送往接口。

普通对话与创作的滚动摘要、全历史时间线和逐轮增量时间线共用事件提炼规则。完整保留独立事件、必要因果、转折、结果、时间跨度与未决线索，合并小动作并去除无关修辞、感官渲染和重复心理；有后续影响的细节与约束仍保留。详略由事实与影响决定，不随原文篇幅扩写，不设置固定字数、句数或节点数上限；模型请求仍受实际上下文和输出预算约束。Room v35（20 个实体）不变，旧消息、摘要、时间线和备份继续兼容。

本轮合成对话与本机 HTTP 回归用于验证发送、失败恢复及基本操作流程；设备安装、触控和真实厂商模型的语义效果仍需单独验收。源码验收、Release 构建、签名与包内容核查、main/版本标签推送和唯一 APK 公开下载核验均已通过。最终结果见 [最新发布说明](release-notes/latest.md)、[UPDATE_LOG.md](UPDATE_LOG.md) 与 [walkthrough.md](walkthrough.md)。

## v2.8.10：长会话压缩实际生效

确认 L2/L3/L4 或自定义压缩比例后，会实际整理较早历史并重新计算占用；修改同一档位的轮数/比例也会应用。较早原文由已保存摘要承接，实际请求只带该策略保留的完整轮次与置顶内容，原始聊天记录继续保存在本机。摘要追加几轮时，占用不会重新计入已覆盖的整段历史。

原文保留窗口与摘要覆盖范围独立，切回浅档时可按预算恢复原文。L0/L1 不主动调用摘要模型；在这两个档位点击“应用滚动摘要并压缩”，会在确有可退休内容时切换到保留最近 8 轮的滚动摘要策略。选项草稿不会因滚动丢失，预览不冒充保存；发送等待已确认策略保存，取消整理保留已保存档位，失败可重试。生成中的变更明确在下一轮生效。

跨 API 配置的摘要、预览和请求使用当前配置的模型窗口，超限降级只收紧窗口；复制会话映射有效摘要边界，普通设置保存不会回写旧摘要。普通对话与创作共用这些修复，数据库和旧聊天/备份兼容。此次 2.8.10/196 按用户要求将这些改动构建为 APK；2026-10-17 冻结验收的编译、完整单测与 Lint 均实际执行，标准脚本退出 0，85 套件/797 项全通过，Lint 0 Error/95 Warning，输入哈希一致；2026-10-18 已完成公开发布核验。构建及发布结果见 [最新发布说明](release-notes/latest.md)、[UPDATE_LOG.md](UPDATE_LOG.md) 与 [walkthrough.md](walkthrough.md)。本机 HTTP 合成回归不代表真实模型质量或设备安装验收。

## v2.8.9：上下文压缩修复

预览、手动压缩与发送共用预算，读取会话或所选模型的上下文窗口；摘要按实际对话顺序记录覆盖边界，重新生成的高编号回复不再误吞后续低编号消息或重复整理。保留最近完整用户轮次及完整置顶轮次，L2 按设置保留，L3 保留最近 4 轮、L4 保留最近 1 轮；这些是预算内目标，预算不足时继续压缩较早轮次，最新完整轮和置顶内容不会静默丢弃，L4 也保留历史摘要。

长历史逐段合并旧摘要，分块预算计入完整模板、记忆约束和输出空间；模型返回完整但超预算摘要时最多再做一次语义缩短，失败、取消或原文变化时保留原始消息及上次摘要。正常完成的无句号待办、文件名不会被清洗删除。上下文面板提供“取消整理”，“立即压缩”会在保存档位后实际整理历史，刷新状态不会提前清除忙态。

实现参考固定版本的 [Aider](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/history.py)、[LangMem](https://github.com/langchain-ai/langmem/blob/48e3c11f5bb527282c7d5339c6a87a0b35abccfc/src/langmem/short_term/summarization.py) 与 [OpenCode](https://github.com/anomalyco/opencode/blob/bc5ebf00a4c169ece10f276e6ce02eaf18c326e6/packages/core/src/session/compaction.ts) 的轮次切分、预算和覆盖记录思路，没有增加依赖或复制源文件。摘要仍可能遗漏细节；可审阅、编辑或清除摘要，原始聊天记录始终保留。Room v35（20 实体）不变。

## v2.8.8：七款 Bot 与状态动效

本版纳入三款极简 Bot **圆圆、方方、扁扁**与四款线条机器人 **圆豆、方糖、团子、小方**。设置 → 界面与外观 → 模型标识，关闭“显示模型头像”后自由选择；提供放大的实时预览和待机、连接、思考、回复、完成五种状态，再次点击完成可重播。普通对话与创作共用，头像仍默认显示，原有同心圆、轨道、棱镜、声纹选择保留。

三款极简 Bot 的两只自然直胶囊眼始终同形、同高，共同看向目标并同步短眨。状态主要靠姿态和节奏区分：连接时左右探看、身体跟随，思考时抬眼侧倾并停顿，回复时按短句轻点，完成后一次点头收势。三款比例和节奏各异，扁扁为86×64的圆角横矩形。快速切换从当前姿态过渡，历史消息保持静止，最新成功回复完成收势后可进入符号待机，支持系统减弱动态和后台停帧。[三款同轨迹预览](design/bot-motion-v4/index.html)与[连续动图](design/bot-motion-v4/motion-reel.gif)可直接比较；网页样稿不能替代设备实时验收。

[上一版方圆预览](design/bot-motion-v3/index.html)保留作设计对照。

三款极简Bot的外部状态符号统一放在右上角：连接信号沿右上斜向发出，三级弧依次亮起、共同保持后淡出；思考先冒尾泡再出现主泡，整组向右上浮动并变大；输出为带尾巴的说话气泡，内部三点依次亮起；待机Z从小变大、向右上飘起后消散，完成闪星只出现一次。连接、思考、输出、待机的循环分别为6、6.4、5.6、7秒，均有明显停留。待机时双眼在约1.2秒内一起缓缓向下看，表达犯困，保留自然眼形和稳定身体；完成收势后自然进入该过程。最新成功回复和设置实时预览可进入待机，历史消息与选项缩略图保持原来的正视静姿，减弱动态直接显示下看静姿；动作评审网页默认完整播放，也可自行切换系统或减弱模式，应用继续遵循系统减弱动态。

已删除被否决的讯号/浮岛候选，保留装帧；[五套新主题预览](design/theme-candidates-v3/index.html)提供瓷光、字场、映夜、织页和游园，各自具有独立页面结构与细节，尚未应用Android。

## 功能

- 多 API 配置、模型切换、流式回复、思考与高级参数。
- 回复方向选择、消息编辑与重新生成、后台生成。
- 按会话开启输入注入回复，前台保留原始输入，后台追加原文并发送自定义触发语。
- 角色卡、世界观、故事时间线与待确认增量提取。
- 智能记忆、上下文预算、摘要与主动压缩。
- 联网搜索、图片与附件输入、OCR 辅助。
- 对话文件夹、历史记录、使用统计、个性化与备份恢复。
- 聚焦对话与侧栏工作台两种首页布局，共享会话、创作、统计、设置四个入口。
- 墨白、晴空、夜航、索引主题，以及独立的创作阅读样式与流式动画设置。

提取结果需要模型遵守格式指令，并由用户确认后保存；不保证所有服务兼容或每次提取成功。HTTP 默认关闭，白名单仅本机保存；HTTP 不加密消息和凭据，优先使用 HTTPS。

## v2.8.6：创作工作区与可靠上下文

创作页按“作品 / 人物与世界 / 世界书”组织。新作品只需名称、写作方式、写作要求和模型，人物与世界可稍后准备。作品卡直接进入正文、工作台、会话设定和时间线；故事工作台按“写作 / 人物与世界 / 会话设定 / 时间线 / 世界书”切换。设定与时间线复用普通对话的增删改、启停、历史梳理、增量提取、断点继续和草稿审核。模型与上下文使用共享设置；本故事人物/世界保存为独立副本，取消人物参与不删除定制资料。

头像与背景历史支持删除，当前使用的图片保留；删除记录防止历史自动重新收录。六款浅色与六款深色预设背景保持所选颜色，主题切换仍回到对应主题纯色。阅读排版、正文字体分别有“应用于普通对话”开关；思考胶囊、开关、正文和操作文字随主题及实际底色适配。

对话设置 → 模型与生成中可启用多方向回复，并选择 2–4 个候选方向；创作从故事工作区 → 模型与生成进入。稍后选择可由底部待选提示继续。上下文面板可查看、编辑与重新生成摘要。压缩按完整轮次保留最近消息和置顶轮次，连续分块覆盖旧历史；失败或截断不推进覆盖位置，原文不删除。自 v2.8.12 起，编辑源消息保留已有摘要，用户可主动重建；生成期间的原文或人工摘要修改不会被迟到结果覆盖。上下文计数仍为估算，实际模型窗口与服务限制由接口决定。

统计页按供应商和模型筛选，显示实报/估算来源、正式及辅助调用用途、重试与中断、首段等待、完成耗时 P50/P95。缓存属于输入，思考属于生成，避免重复计数；历史记录缺失的来源和计时不会反推。这是本机观测统计，不是服务商账单。

## 首页与个性化

在“设置 → 界面与外观”选择**聚焦对话（底栏）**或**侧栏工作台（左栏）**。聚焦对话优先展示新对话与最近会话；工作台突出继续故事与创作资料。两种布局使用相同的会话、创作、统计、设置入口，保留搜索、文件夹、历史、置顶、多选及会话管理操作。列表紧凑模式和“显示继续故事”开关对两种布局都生效；隐藏或私密故事不会出现在普通首页推荐中。

配色、首页布局、阅读排版和动画独立保存。主题可选墨白、晴空、夜航、索引，旧用户默认保留经典配色，浅色/深色/跟随系统仍单独选择。创作正文可选沉浸叙事、简洁正文或分栏上下文；分栏显示已保存的故事资料，宽屏并排、窄屏折叠，继续支持 Markdown 与消息操作。流式动画可选细光标、微声波或墨环，系统关闭动画时显示静态指示。

**v2.8.7 阅读与展示更新**：沉浸叙事中已发送的用户消息采用透明底、左侧细线和留白，取消右侧用户头像，保留附件、引用与消息操作。普通对话需要开启“阅读排版也用于普通对话”才采用此布局，仅切换字体不会改变气泡。设置 → 界面与外观 → 创作阅读页新增“显示思考气泡”，默认开启；关闭后普通对话与创作均隐藏思考胶囊和展开内容，保留轻量模型身份、生成/重试/回复方向及错误提示，耗时和思考 Token 回到消息底栏。这只影响展示，不更改模型请求、消息保存或统计。本次安装包包含这些改动。

外观设置中的“模型标识”默认显示头像，关闭后可选三款极简 Bot、四款线条机器人或同心圆、轨道、棱镜、声纹。不同状态的动效遵循系统减弱动画；原几何标识结束后静止，最新成功回复的极简 Bot 可进入待机。它与思考气泡及正文末尾流式动画独立，开启头像时保留已选样式。纯色背景包含纯白与纯黑，总计 14 款，深浅模式都保持原色。本版纳入上述模型标识选择，构建和发布结果见最新说明。

[五套新主题设计预览](design/theme-candidates-v3/index.html)提供瓷光、字场、映夜、织页、游园；[装帧](design/theme-directions-v2/index.html)保留。讯号、浮岛已从当前候选文件中删除。墨白是已加入Android的正式主题；其余新候选保持HTML/PNG预览。

首页方案 01/02 已落地；创作书架、索引仪表盘、时间线叙事和一页任务仍是设计预览，不是应用内选项。详情见 [设计研究](design/roleplay-rework/research.md)、[主题与阅读交互样稿](design/roleplay-rework/comparison.html)和[首页布局方案](design/roleplay-rework/layout-options.html)。HTML 与截图均为合成内容，不代表 Android 设备验收。

## 世界书与聊天修复

世界书 JSON 可从角色与创作页顶部或设置中的世界书区域导入。支持 SillyTavern 对象、Character Book 数组及角色卡内嵌世界书的基础内容。导入前展示兼容提示，保存为**默认关闭的独立副本**，不覆盖同名资料，也不自动绑定故事。先在世界书列表检查并启用书目及词条，再到普通对话设置的世界书区域，或故事工作台的“世界书”页启用并绑定书目。

书目可选“全部已启用”或“仅选中”；“仅选中”且未选任何书时不会发送世界书。词条按本轮输入和压缩前最近 4 条有效消息原文触发，旧回复变体与排除消息不参与，旧置顶不会冒充近期消息。常驻词条直接参与；统一受 1500 个估算 token 预算限制，过大条目跳过。预算保留优先级不代表模型指令权限。

高级正则、宏、位置/深度、概率及未知扩展尚未完整兼容；预检会说明损失，相关条目默认停用，原始扩展不会保存。角色卡导入仅提取世界书部分，不导入角色本体。当前不承诺无损导出或与外部客户端完全相同的行为。

创作提示保留用户全局规则与故事要求，去掉每张人物卡重复的固定文风铁律；没有记忆条目时仍携带已保存的当前故事时间。重新生成恢复原附件与 MIME 信息，故事设置串行保存后再读取发送。流式回复结束落库保持列表身份和当前阅读位置，重新进入生成中的会话可继续看到活动回复。

本版自动验证与 APK 元数据见 [最新发布说明](release-notes/latest.md)。Room保持v35（20 实体），既有请求计量元数据与保留旧记录的34→35迁移不变，本版没有数据库结构变化。设备安装、启动、输入法及真实接口仍需验收。

## 隐私与上传要求

每次提交、推送或上传附件前，**必须核查并确保内容不含任何用户个人信息或隐私**。覆盖完整文件、待上传历史与元数据、图片及附件；发现疑点立即停止上传。真实凭据、私人接口、本机用户名路径、聊天记录与备份不得进入仓库。

示例使用合成数据、文档保留地址或 `.test` / `.invalid` 域名。配置和真实地址仅在自己的设备填写。应用会将请求内容发送至所选模型或搜索服务，本地存储不意味着数据从不离开设备。

历史对象与平台缓存不因新提交自动消失；已发现的历史隐私残留尚需单独处理，不宣称已彻底清除。维护执行清单见 [WORKFLOW_GUIDELINES.md](WORKFLOW_GUIDELINES.md)。

## 从源码运行

需要 JDK 17、Android SDK 34；版本依赖以 Gradle 配置为准。将本机 SDK 路径放入未跟踪的 `local.properties`，不要提交本机配置或签名文件。

```powershell
pwsh -File scripts/verify.ps1
git diff --check
```

验证脚本在单次 Gradle 调用中完成编译、全量单测与 Lint，保留 `--no-daemon`、正常增量检查和本地构建缓存，输出任务耗时与执行/缓存状态。需要指定可写缓存时传 `-GradleUserHome <本机目录>`。默认仅显示失败和异常，可用 `-VerboseTests` 查看详细测试日志；`-RerunTests` 只强制单测，不重编译全部依赖。验证前先冻结源码，脚本会拒绝验收期间输入变动的结果；同一代码通过后只改文档，无需再次全量检查。没有缩减测试范围或 Lint 规则。

源码公开用于正常开发与审查；不再展示旧版本发布列表。数据库为 Room v35（20 个实体），升级禁止破坏性迁移。构建配置可能包含本机 JDK 指向，请在自己的环境使用有效 JDK 17。
