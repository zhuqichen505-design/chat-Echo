# Echo 2.8.12

本版新增默认关闭的“输入注入回复”，将原先需要手动编辑模型回复、再发送触发语的操作合并为一次发送，并保持聊天界面的阅读方式。另纳入上一版发布后尚未出包的 bot、时间线和摘要请求修复。

本轮编译、完整单测与 Lint 已通过，Release 构建和签名核验已完成。设备交互与真实接口效果仍按下文边界验收；Git 与公开附件的实际发布结果见走查记录。

## 输入注入回复

入口为“对话设置 → 提示与记忆 → 输入注入回复”，默认关闭。开启后填写自定义触发语，文字完全由用户决定，不预填固定续写指令；仅空格或换行不能保存为有效触发语。

用 A 表示上一条模型回复，P 表示本次输入，T 表示本轮保存的自定义触发语：

| 消息 | 界面显示 | 后台保存并供模型使用 |
| --- | --- | --- |
| 上一条模型回复 | 原回复 A | A + `\n\n` + P |
| 本轮用户消息 | 输入原文 P | 自定义触发语 T |
| 下一条模型回复 | 正常显示新回复 | 正常生成和保存 |

`\n\n` 表示两个换行。后台先保存原回复、两个换行和输入原文，再向模型发送本轮触发语；不额外添加标题、标签、引号、解释或固定模板。用户输入不会显示在旧模型回复末尾，也不会在用户气泡中变成触发语。

- 显示内容、模型正文和注入目标分别持久保存。失败重试和重新生成复用本轮保存的内容，不重复追加，也不读取后来修改的触发语。
- 关闭开关后，新消息恢复普通发送流程，原有历史的显示保持稳定；已有注入轮次继续保留当时的模型上下文语义。
- 编辑与删除关联消息、回复版本、编辑重发、分支、备份恢复和会话导入同步处理注入关系；相关检索继续使用实际输入。
- 没有可注入的上一条有效模型回复时，本次按普通消息保存和发送。纯附件消息继续使用原附件流程，文字与附件组合保留附件。

## 编辑与滚动摘要

手动编辑消息正文和自动注入都保留已有滚动摘要的正文、覆盖水位与更新时间，不自动清空或使其失效。因此，已经被摘要覆盖的旧正文修改后，摘要暂时仍保留原有内容。

需要让摘要反映修改时，由用户主动重新压缩或重新生成摘要，软件按编辑后的原文重建。旧摘要会保留至新结果完成校验并保存；请求失败、取消或并发原文/人工摘要修改不能让迟到结果覆盖当前内容。

## 同时纳入的改进

- **Bot 与状态符号**：放大 bot 本体及右上角状态符号，普通、生成与历史消息展示同步调整。
- **时间线与设定**：对话设置新增独立时间线开关；关闭后不向模型注入时间线，也不启动后台增量提取，已有记录仍可查看。时间线使用紧凑布局，提取去除无关细节，保留关键事件、因果、时间跨度、约束与未决线索。
- **摘要请求参数与解析**：非流式和流式摘要共用参数，按模型实际能力选择输出限制字段和较低的思考档位，为推理预留完成额度；统一 API 路径，支持结构化正文及跨块、多段思考标签。
- **二次语义缩短**：首轮摘要完整返回但超过保存预算时，使用紧凑提示携带完整首轮正文再次缩短，避免小窗口在第二次请求发出前因长模板占满预算而失败。
- **失败保留**：双摘要请求失败仍报告真实原因，保留原始消息、旧摘要与覆盖水位，不用本地抽取冒充模型摘要成功。长会话可能需要多个请求，整次整理的耗时取决于分段数和接口响应。
