# Echo 2.8.22

版本 2.8.22/208，基线 `f886e43`，Room v37（20 个实体）不变；源码验收与 Release 构建已完成，Git / Release 尚待执行，当前尚未发布。

- 新增默认开启的全局“流式输出”开关，入口为“设置 → 模型失败与重试”。关闭后等待完整回复返回，适用于不支持流式请求的服务商；对新请求生效，同一请求的重试和备用 Key 保持原选定模式。
- 非流式模式支持 OpenAI 兼容与 Anthropic 协议，保留正文、思考、完成原因及用量；关闭时禁止摘要、命名、翻译和辅助任务自动进入流式保底。
- 修复等待完整回复时主动停止后，连接关闭被误判为网络错误并自动重试的问题；停止等待会取消本次请求，原有传输错误和超时处理保持。
- 不修改原 API 地址、密钥或模型配置，保留首个有效回复的 120 秒等待边界。非流式长推理可能达到该边界；关闭后能否恢复谷歌模型，取决于服务商是否支持非流式请求，尚未经过真实服务商验证。

本轮临时方案：独立持久化开关，避免旧设置表单覆盖；关闭后发送 `stream=false`、`Accept: application/json`，OpenAI 兼容协议不发送 `stream_options`，等完整响应体返回后解析正文、思考、完成原因和用量；Anthropic 完整解析 JSON 的正文 / 思考内容块、停止原因和缓存用量。消息保存、取消、变体与统计复用原有流程，数据库无迁移。

涉及 `PersonalizationManager.kt`、`SettingsRetryControls.kt`、`SettingsScreen.kt`、`AiRepository.kt`、`Models.kt` 和版本配置；偏好持久化、旧表单不覆盖、双协议响应、参数 / 请求头、取消、模式切换和辅助流式限制由既有领域测试承接。
