# Echo 2.8.32

版本 2.8.32/218，Room v37（20 个实体）不变。

## 对话滚动

- 修复“模型报错后页面不跟着下滑”：请求失败时正文可能一个字都没有，气泡高度全部来自状态胶囊文案与实时 Key 报错明细，旧逻辑只比较正文长度，因此完全不跟随。现在状态文案与报错明细变化同样推动页面上滑。
- 失败或中断的回复落库后，按“发送后贴底”的同一套时间点跟随到底部，不再只露出报错的上半截；手指拖动列表会立即让出，不抢阅读位置。
- 用户主动点“停止”不触发贴底，避免停止后正文变短造成跳动。

## 输入框

- 修复“点击输入框时输入法被收起、正在输入的字消失”：删除依赖窗口 Insets 的“输入法显示过又被收起”判定——显示/隐藏动画中出现一帧读数为不可见就会在点击时清焦重建，收起键盘并丢弃候选中的拼音。
- 现在只有输入连接确实失效（键盘在屏幕上却打不出字、旧会话已结束）才重建会话；其余情况已聚焦的输入框不再清焦、也不重复请求焦点，只按需补显示键盘。
- 重建会话时，即使焦点事务没有被立即观察到，也一定会重新聚焦并补回键盘，不再出现“点一下键盘就没了”。

## API 配置页

- 连接、密钥、模型不再分页签，改为同一页从上到下连续滚动：1 连接 → 2 密钥 → 3 模型，滚动位置统一，长表单不再被切成三个互不可见的页面。
- 每个分区前新增标题：序号徽标、名称与当前摘要（密钥段显示已录入数量与轮询开关状态，模型段显示已添加数量）。
- 新建 API 配置时“启用多 Key 轮询”默认关闭；同一地址与协议已保存过策略时仍原样载入，不会被新默认值覆盖（包括早期没有开关键的旧策略）。
- 轮询数字无效的提示改为指向“密钥分区”。

## 设备与真实接口验收边界

当前无连接设备，未验证安装、启动与以下交互，需人工复验：

- 制造一次请求失败（错误地址或无效 Key），确认报错气泡出现后页面推到其底部；在报错前手动上滑阅读旧消息，确认不被抢回视口。
- 打字过程中点击输入框定位光标（含拼音候选未上屏）、连续快速点击、按返回隐藏键盘后再点、键盘可见却打不出字时再点，确认键盘不再被收起、文字不丢失；分别使用普通输入法与悬浮输入法复验。
- 新建 API 配置时确认“启用多 Key 轮询”默认关闭；编辑同一地址的既有配置时确认读到原策略；连接 / 密钥 / 模型三段在同一页连续滚动，分区标题与摘要在手机与宽屏、深色主题下显示正常。
