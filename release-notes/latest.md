# Echo 2.8.14

本版精简自动时间线，新增可自定义的多 Key 轮询与冷却，并修复删除后旧上下文残留、备用 Key 恢复后仍显示错误及暂停状态异常。

## 时间线与多 Key

- 自动时间线只保留影响后续的关键行动、决定、结果、必要因果和未决线索，减少寒暄、修辞与日常流水账。通常 20～72 字，新增或更新后的整条事件上限 96 字；超长先尝试语义精简，失败保留原节点并提示，不直接截断事实。已有确认节点和手工梳理不追溯裁剪。
- API 配置 → 密钥新增“多 Key 轮询与冷却”，支持轮流优先、最近成功优先、列表顺序优先，以及失败降权、冷却阈值与时长、递增上限、自动重置、成功恢复和全部冷却时单 Key 探测；可立即重置健康记录。
- 默认轮流优先，失败 1 次后冷却 300 秒（5 分钟），重复失败递增冷却至最多 3600 秒（1 小时）；距上次失败 86400 秒（24 小时）或再次调用成功后清除失败记录。全部 Key 冷却时默认提示稍后重试，避免逐个重复失败。
- 策略和健康记录按 API 地址及协议共享，跨请求和重启保留，聊天与辅助请求统一使用。轮询草稿保存后生效，取消不保存；手动健康重置立即生效。备用 Key 总开关与单次错误重试仍在“模型失败与重试”设置。

## 删除、恢复与暂停修复

- 删除消息或后续消息时同步清理隐藏注入、旧摘要和由这些消息直接生成的普通/角色记忆，旧孤立来源不再进入请求。回复方向快照的来源变化时要求重新发送，避免继续使用删除前内容。
- 对话副本和分支的记忆关联各自新消息，删除原消息不误伤副本；分支不会继承截止点后来源的记忆。人工改写的记忆独立保留。
- 备用 Key 开始返回正文或思考后清除过期错误和重连提示，保留真实思考；真实请求失败与流式中断继续显示原因。顶部错误和上下文提示的背景与文字同步退出。
- 暂停保留真实正文和思考，统一中性“生成已停止”，不再把 Key 尝试记录拼入回复，不重复显示停止占位。修复正常完成与暂停并发时的重复保存/计量，以及旧轮回调覆盖新轮状态。
